# ADR-0011：项目归档更新采用稳定来源与三方快照合并

- 日期：2026-10-30
- 状态：**Accepted**，用户于 2026-10-30 授权分阶段实施；P0 基础模块进行中，未通过测试或桌面验收。
- 产品流程、字段规则、阶段与验收唯一详述：[项目导入更新与三方合并方案](../plans/2026-10-30-project-import-update-merge.md)。

## 背景

当前 `.aicanvas` v2 导入始终创建新项目和数据目录，源机器文件身份重新识别。用户需要把项目交给他人修改后更新原项目，也需要合并双方并行修改，冲突时由用户选择。

现有包没有共同版本与协作身份；同名、更新时间、节点 ID 相同或文件同字节不足以证明可靠来源。原生直接解包到目标目录、逐项目保存以及当前内存保存屏障，也不足以保证整部剧合并失败时不改变原项目。

## 备选方案

| 方案 | 收益 | 问题 | 建议 |
|---|---|---|---|
| 新包整体覆盖已有项目 | 实现和使用路径短 | 无法保留本机并行修改；不能识别删除/修改冲突。 | 不作为默认更新能力。 |
| 双向差异，逐项二选一 | 不需要共同历史，旧包能用 | 无法判断“只对方修改”或本地已删除；人工选择多。 | 保留为明确标识的旧包降级路径。 |
| 来源身份 + 共同基线 + 三方快照合并 | 离线往返可自动处理非冲突变化，可解释冲突来源。 | 需要持久基线、身份映射、事务及恢复机制。 | **推荐。** |
| 实时 CRDT/多人协作服务 | 面向持续在线协作 | 引入服务、会话与更广的状态改造；不直接解决现有离线包。 | 不纳入本专项。 |

## 决策一：协作身份与本机身份分离

使用 lineage、类型化逻辑实体身份及本机映射。普通导入副本可继续同一协作来源；明确独立复制创建新来源。更新保留目标本机项目身份，不按名称关联，不借 S3 身份代替项目身份。

收益是可以跨电脑、分集和重复导入保持可识别关系；成本是需要维护映射并覆盖复制/新增/删除语义。缺失映射不能凭名称补齐后静默提交。

## 决策二：版本为不可变规范快照，记录父关系

以规范正文、摘要、规范版本和父关系证明共同基线；合并前捕获本机未导出的编辑，成功合并记录两侧父版本。三方合并按领域字段与原子组进行，不使用通用递归 JSON 覆盖。

收益是连续往返与“保留本地”决定可解释、可重复核对；成本是锚点空间和父链管理。多个不可比较基线、缺少基线正文或规范不兼容时保守降级，不猜最新时间。摘要只证明材料一致性，不构成来源认证或执行授权。

## 决策三：旧包可人工对比，但不伪造共同历史

v1/v2 继续支持新建导入；选择更新时可补最初交接包，经用户确认作为外部基线，否则采用明确的无基线双向人工比较。实体单侧缺失不能自动解释为删除。

收益是现有项目可逐步进入协作；代价是首次人工关联和旧包冲突较多。新来源身份不等于获得过去共同版本，不能把两侧当前内容中的一侧强行作为基线。

## 决策四：媒体先暂存，数据库整批提交，旧文件保留

复用统一项目传输入口、保存队列及路径/媒体基础设施；新增固定原生暂存操作，绝不在预览时解到已有项目目录。发布新媒体之后，在同一 IDB 事务提交整部剧、摘要、文件记录、版本和操作完成标记。

所有项目写入遵守持久化 epoch，补足跨实例旧自动保存保护；当前内存 revision 和资产库屏障不能替代它。事务后 Store 投影及原生收尾可恢复，不能把磁盘和 IDB 描述成单一 ACID 事务。

收益是失败不产生半套项目更新，重启可核对；代价是暂存和恢复点占用、清理延后，以及需要核对所有项目写入口。保留不确定文件优于误删，清理交由有归属校验的流程。

## 决策五：运行状态与授权不参与合并

用户已确认业务合并范围为画布、分集、设置、资产。聊天/记忆仅可选追加来源副本；不续接本机会话、不覆盖本机记忆。厂商凭据、文件授权、云绑定、AgentTask、插件执行信任及付费生成运行状态不导入为可执行能力。

收益是离线协作不扩展权限，不复活历史任务；成本是接收端可能需要重新绑定模型/工作流，对某些复杂原生产物需要专门领域适配。无法安全恢复时必须明确阻止采用，不绕过现有安全与项目 guard。

## 结果与评审边界

推荐使用已有 React/Zustand、IndexedDB、固定 Worker 和 Rust tar/gzip/摘要/路径能力，不引入云服务或新依赖。实现仍须分别覆盖应用主窗口、其他实例、后台写入、归档不可信输入、分集引用与真实媒体文件。

用户已授权按本 ADR 与主方案分阶段实施；测试和验收仍遵守仓库的独立授权规则。本 ADR 不宣称性能或测试结果，阶段状态与未完成项以主方案为准。
